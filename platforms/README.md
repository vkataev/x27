# Platforms

**Tenstorrent** is the most architecturally specialized and the most explicit. It gives you a two-dimensional mesh of small cores with local scratchpad memory and an on-chip network. The compiler must decide where every operation runs, where every tensor lives, and how data moves between cores. This can deliver excellent performance per watt on workloads that map well to the mesh, especially sparse or irregular neural networks. The disadvantages are a much smaller software ecosystem, a steeper programming curve, and the risk that a bad compiler mapping leaves the chip memory-bound or network-bound. It is best suited for inference and specialized training where the workload is well understood and the team can invest in tuning the mapping.

**NVIDIA** is the most general-purpose and the most mature. Its Streaming Multiprocessors and cache hierarchy are designed to handle a huge variety of parallel programs, not just neural networks. CUDA has been around for many years, so tools, libraries, and expertise are widely available. The hardware hides most scheduling and caching details, which makes it easier to get good performance quickly. The disadvantages are higher power consumption, higher cost, and the fact that performance can still collapse when memory access patterns are not coalesced or when the working set exceeds the cache hierarchy. It remains the default choice for datacenter training and general high-performance computing.

**Apple Silicon** sits between a mobile System on Chip and a desktop System on Chip. Its biggest advantages are integration, energy efficiency, and the unified memory model. Because the central processing unit, graphics processing unit, and Neural Engine share one coherent memory pool, data movement overhead is very low, which accelerates workloads that frequently hand data between engines. The operating system and frameworks hide much of the complexity. The disadvantages are limited peak throughput compared to a large discrete graphics processing unit, less flexibility for custom kernels because the lowest-level hardware interfaces are not exposed, and limited scalability since it is designed for consumer devices rather than rack-scale datacenter training
